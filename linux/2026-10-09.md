## 2026-10-09 리눅스 8주차 Day2

**오늘 배운 내용**
- 캐싱 전용 네임 서버 구축

**개념**
- 캐싱 전용 네임 서버: PC에서 URL로 IP주소를 얻고자 할 때, 해당하는 URL의 IP주소를 알려주는 네임 서버
  - 로컬 네임 서버라고 지치한 컴퓨터가 캐싱 전용 네임 서버의 역할을 수행(책에선 Server가 그 역할)

**명령어**
- systemctl enable named: 네임서버 상시 가동
  
**헷갈렸던 것 / 에러**
- 없음
 
**정리**
- 로컬 네임 서버가 IP 주소를 얻는 흐름(p.520~521)
    - a. 웹 브라우저 주소창에 URL 입력 (예: www.nate.com) ①
    - b. /etc/resolv.conf 조회 → `nameserver IP주소`로 설정된 로컬 네임 서버 확인 ②
    - c. PC가 로컬 네임 서버에 질의 ③
    - d. 로컬 네임 서버가 자신의 캐시 DB 검색 ④
    - e. 로컬 네임 서버가 위에서부터 차례로 질의
        - 1) ROOT(.) 네임 서버에 질의 ⑤ → 응답 ⑥
        - 2) COM 네임 서버에 질의 ⑦ → 응답 ⑧
        - 3) nate.com 네임 서버에 질의 ⑨ → 응답 ⑩ (www = 111.111.111.111)
    - f. 로컬 네임 서버가 PC에 응답 ⑪
    - g. PC가 획득한 IP 주소(111.111.111.111)로 네이트 웹 서버에 접속 ⑫

- 핵심 정리
    - PC는 로컬 네임 서버에게 질문함
    - 로컬 네임 서버가 혼자 전 세계 모든 도메인을 관리할 수 없으므로 ROOT → COM → nate.com 순서로 물어봄
    - 원 숫자(①~⑫)는 교재 그림의 번호와 같음

- 실습: Server 가상머신을 캐싱 전용 네임 서버로 구축
  - a. 네임서버와 관련된 패키지 설치(dnf -y install bind bind-chroot)
  - b. /etc/named.conf파일 수정(p.523)
  - c. 서비스 작동(systemctl restart/enable/status named: 네임서버 재시작/상시가동/상태확인)
  - d. 방화벽 설정(firewall-config에서 dns설정)
  - e. 작동 테스트(dif @네임서버IP 조회할URL)
  - f. 다른 클라이언트에서 Server 네임 서버를 사용하도록 설정
    - Clien 가상머신의 예시): gedit /etc/resolv.conf 수정(이 파일에서 IP주소를 192.168.111.100(Server의 IP)로 변경)
